## 2. Lab Description

This lab demonstrates a **Reflected Cross-Site Scripting (XSS)** vulnerability in the search functionality of a blog application.

The application reflects user-controlled input inside an HTML attribute and HTML-encodes angle brackets (`<` and `>`). This prevents an attacker from injecting new HTML elements directly.

However, double quotes are not properly handled, allowing an attacker to break out of the existing attribute and inject additional HTML attributes.

In this solution, the injected `autofocus` attribute attempts to focus the existing element automatically, while the `onfocus` event handler executes JavaScript when the element receives focus.

A dummy attribute, `x=""`, is also added to accommodate the original closing quote generated by the application and maintain valid HTML markup.

**Objective:** Inject an HTML attribute that triggers the JavaScript `alert()` function.

## 3. Vulnerability Analysis

The vulnerability exists because the application reflects attacker-controlled input inside a quoted HTML attribute without properly encoding double quotes.

### Source: Search Parameter

The application accepts user input through its search functionality.

For example:

```http
GET /?search=test HTTP/2
```

The supplied search term is sent to the server through an HTTP request.

The application then reflects this input into its HTML response.

### Injection Context: HTML Attribute

Unlike previous labs where the input was reflected into the HTML body, this application places the search term inside an HTML attribute.

For example, the resulting HTML might look like:

```html
<input type="text" value="SEARCH_TERM">
```

The search term is placed between double quotes.

This is important because the browser interprets everything between the quotation marks as the attribute value.

### HTML Encoding

The application HTML-encodes angle brackets:

- `<` becomes `&lt;`.
- `>` becomes `&gt;`.

This prevents direct injection of additional HTML elements.

However, the application does not properly encode double quotes.

An attacker can therefore use a double quote to terminate the existing attribute value and introduce new attributes.

## 4. Understanding HTML Attribute Injection

HTML elements can contain attributes that define their properties and behaviour.

For example:

```html
<input type="text" value="hello">
```

Here:

- `type` specifies the input type.
- `value` specifies the input's initial value.

The value of an attribute is enclosed in double quotes.

If attacker-controlled input is inserted into this context without encoding double quotes, an attacker may escape the existing attribute.

For example, consider:

```html
<input value="USER_INPUT">
```

By injecting an additional double quote, the attacker can terminate the original `value` attribute and introduce other attributes.

This technique is known as **HTML attribute breakout**.

## 5. Understanding the Attributes Used in This Lab

The exploit relies on three important attributes.

### A. `autofocus`

The `autofocus` attribute tells the browser to automatically focus an element when the page loads.

Example:

```html
<input type="text" autofocus>
```

When the page loads, the browser attempts to place focus on the input element.

### B. `onfocus`

The `onfocus` event handler executes JavaScript when an element receives focus.

Example:

```html
<input type="text" onfocus="alert(1)">
```

When the input receives focus, the JavaScript inside the event handler executes.

### C. Dummy Attribute: `x=""`

The application generates an original closing quotation mark after the reflected input.

The injected `x=""` attribute accommodates this remaining quotation mark.

This helps maintain valid HTML markup after the attribute injection.

## 6. Exploitation Methodology

### Step 1: Identify the Vulnerable Functionality

I accessed the application's search functionality and submitted a normal search term.

I observed that the application reflected the supplied input inside an HTML attribute.

### Step 2: Identify the Injection Context

I inspected the reflected input and identified that it was placed inside a double-quoted HTML attribute.

I also identified that the application encoded angle brackets.

Therefore, directly injecting a new HTML element was not possible.

However, double quotes were not properly handled.

This provided an opportunity to escape the existing attribute and inject additional attributes.

### Step 3: Identify an Alternative Execution Mechanism

Instead of injecting a new HTML element, I used attributes that could execute JavaScript on the existing element.

I identified two useful attributes:

- `autofocus` to automatically focus the element.
- `onfocus` to execute JavaScript when the element receives focus.

### Step 4: Craft the Payload

I used the following payload:

```html
" autofocus onfocus=alert(document.domain) x=""
```

### Step 5: Payload Breakdown

| **Payload Component** | **Purpose** |
|---|---|
| `"` | Closes the existing HTML attribute value. |
| `autofocus` | Attempts to automatically focus the existing element. |
| `onfocus` | Defines an event handler that executes when the element receives focus. |
| `alert(document.domain)` | Executes JavaScript and displays the current domain. |
| `x=""` | Adds a dummy attribute to accommodate the original closing quotation mark. |

### Step 6: Execution

1. Submit the crafted payload through the search functionality.
2. The application receives the search parameter.
3. The application reflects the input inside an HTML attribute.
4. The injected double quote terminates the original attribute value.
5. The browser interprets `autofocus` and `onfocus` as additional attributes.
6. The autofocus behaviour attempts to focus the existing element.
7. When the element receives focus, its `onfocus` event handler executes.
8. `alert(document.domain)` displays the current domain.

### Result

The JavaScript alert executed successfully, confirming the Reflected XSS vulnerability.

## 7. Root Cause

The root cause was the application's failure to properly encode user-controlled input according to its HTML attribute context.

Although the application encoded angle brackets, it did not properly handle double quotes.

This allowed an attacker to terminate the existing attribute value and inject additional attributes containing JavaScript event handlers.

The application incorrectly assumed that encoding angle brackets alone was sufficient to prevent HTML injection.

## 8. Source, Sink, and Execution Context Analysis

| **Component** | **Analysis** |
|---|---|
| Source | `search` URL parameter |
| Sink | HTML response rendering the search parameter |
| Context | Double-quoted HTML attribute |
| Injection Technique | HTML attribute breakout |
| Attribute Injection | `autofocus` and `onfocus` |
| Execution Trigger | Element receives focus |

### Why Does the Vulnerability Exist?

The application reflects untrusted input into a quoted HTML attribute without properly encoding double quotes.

As a result, an attacker can escape the existing attribute and introduce additional attributes.

The browser interprets these injected attributes as part of the HTML element, allowing JavaScript execution through the `onfocus` event handler.

## 9. Mitigation

Developers can prevent this vulnerability by following these practices:

**1. Context-Aware Output Encoding**

Apply HTML attribute encoding when inserting untrusted input into quoted HTML attributes.

Double quotes must be encoded so they cannot terminate the existing attribute value.

**2. Use Secure Templating Engines**

Use templating systems that automatically perform context-appropriate output encoding.

Avoid manually constructing HTML using string concatenation.

**3. Avoid Blacklist-Based Filtering**

Blocking only angle brackets is insufficient because attackers may inject additional attributes without introducing new HTML elements.

**4. Validate User Input**

Validate incoming data according to its expected format and purpose.

Input validation should complement, not replace, proper output encoding.

**5. Content Security Policy (CSP)**

Implement a restrictive Content Security Policy as an additional security layer to reduce the impact of successful XSS attacks.

CSP should not replace proper output encoding.

## 10. Key Takeaways

1. Understood how Reflected XSS can occur inside an HTML attribute context.
2. Learned how HTML encoding of angle brackets does not automatically prevent attribute injection.
3. Understood how double quotes can be used to escape an existing HTML attribute.
4. Learned how additional attributes can be injected without introducing a new HTML element.
5. Understood how the `autofocus` attribute can trigger automatic focus.
6. Learned how the `onfocus` event handler executes JavaScript when an element receives focus.
7. Understood why a dummy attribute can be used to accommodate the application's remaining HTML syntax.
8. Recognized the importance of context-aware output encoding.

### Most Important Lesson

**HTML encoding must be appropriate for the context in which user input is inserted. Encoding angle brackets alone does not protect an application when attacker-controlled input is placed inside a quoted HTML attribute.**

Understanding HTML parsing and attribute contexts is essential for identifying and preventing attribute-based XSS vulnerabilities.
